# Kursuse kokkuvõte ja refleksioon
```
A) Git on hajutatud versioonihaldussüsteem, mida kasutatakse failide ja koodi muudatuste jälgimiseks aja jooksul. Seda kasutatakse peamiselt IT-meeskondades, et mitu arendajat saaksid töötada sama projekti kallal ilma üksteise tööd üle kirjutamata.

B) Commit on muudatuste salvestamine sinu kohalikus projektiajaloos ehk unikaalne salvestuspunkt. Push on käsk, mis saadab need kohalikud salvestatud muudatused edasi kaugele serverisse, näiteks GitHubi keskkonda, et teised neid näeksid.

C) Harud ehk branches on kasulikud, sest need võimaldavad luua peamisest koodibaasist eraldi koopia. Seal saab turvaliselt katsetada uusi funktsioone või parandada vigu, ilma et see rikkuks töötavat põhiprogrammi.

D) Pull Request on taotlus oma haru muudatuste ühendamiseks peaharuga. Seda on vaja selleks, et teised tiimiliikmed saaksid tehtud töö enne lõplikku liitmist üle vaadata, kommenteerida ja heaks kiita.

E) Git erineb failide USB-le kopeerimisest selle poolest, et Git säilitab detailse ajaloo sellest, kes, millal ja mida täpselt muutis. Samuti suudab Git automaatselt ühendada eri inimeste tehtud muudatused ühes ja samas failis, mis on manuaalselt kopeerides võimatu.

F) Git seostub tihedalt projektijuhtimisega, kuna GitHubi Issues funktsioon töötab nagu ülesannete nimekiri. Neid ülesandeid saab siduda koodimuudatustega ja kuvada visuaalsel Kanban-tahvlil, mis annab tiimile ülevaate projekti seisust.

G) Kavatsen GitHubi kindlasti ka edaspidi kasutada, kuna see on IT-maailmas standardne tööriist. Kasutan seda oma koolitööde ja isiklike programmeerimisprojektide portfoolio hoiustamiseks, et tulevastele tööandjatele oma oskusi näidata.

H) Selle töö juures oli kõige lihtsam veebiliidese kaudu kaustade ja Markdown failide loomine ning teksti vormindamine. Kõige rohkem tähelepanu ja süvenemist nõudis alguses harude loomine ning Pull Requesti loogika mõistmine, kuid praktika käigus sai see selgeks.
```
